How Cognition Credits flow — the token cycle this dashboard tracks show diagram

how credits work, in words

A new mind gets a wallet at creation. Its Cognitive Credits = wallet balance of supported tokens: 1 MENTE = 1 credit; MOCA counts by USD value (USDC support planned). Holding MOCA with no MENTE triggers a small auto-swap to MENTE (the actionable credit). Each user request makes the mind pay MENTE to the collector — gasless for the user: the gas funder first sends a sliver of ETH to the mind wallet in the same moment (visible on-chain as paired transactions). Value leaves the loop via an automatic contract burn (~1.2% lifetime, being confirmed) and enters via Stripe purchases and manual treasury funding. Economy eras: the first generation (≤ Apr 2026) ran on the SWARM token (Ethoswarm) through the same collector hub; SWARM→MENTE migration ~Apr 8–24, 2026 — this dashboard covers the MENTE/MOCA era (SWARM-era integration: see Data gaps). ⚠ Note: a lookalike address 0xD8506866…F111 mimics the collector via zero-value transfers (address poisoning) — never copy the collector address from a transaction history.

AI-inferred interpretation

Everything in this amber zone is inferred — from transfer sizes, timing heuristics, or projections — not read from a ledger. Each block states its method. Treat as triage, not truth.
AI-inferredPayout type classification — skill rewards, credit grants, top-ups

Method: each transfer is classified by its USD value at that day's token price, on the reward grid of its own era (the row's timestamp decides, never the run date): until 21 Aug 2026 13:55 UTC — $0.10 invoke, $1 equip; from 14 Sep 2026 14:19 UTC — $0.05 equip, $0.005 invoke (±12%); a ≈$1 after 21 Aug is a system free top-up (a growth grant, not creator earnings); $3 credit, $5 referral at ±8%; Stripe packs $10/$20/$25/$50/$100 matched on the fee-adjusted value (÷0.94, ±15% — deliveries land ~6% short of the pack price after processing). One shared classifier (classify.py) produces this table, the Telegram digest and the CSV export, so the three always agree, and one grouping layer (group_for) buckets every row as skill rewards (to creator wallets) · credit grants · system free top-ups · top-ups delivered · ops. This is inference from size, not ground truth: a per-transfer memo from the payout contract (requested) would make it exact. The $3 bucket mixes new-user credits and internal top-ups — the internal top-ups sheet is the authoritative split. Pack-sized transfers are size-inferred and may include coupon-delivered credits — not verified revenue (this page does not read the Stripe ledger).

AI-inferredPayout pattern monitor reviewed privately

Method: we look at each earner's payout timing and ask: does it look human-irregular or robotically regular? Statistical pattern checks flag transfer patterns worth review; the specific signals, their cut-offs and their results are reviewed privately, because publishing them would hand anyone gaming payouts a calibration oracle. Cut-offs are judgment calls; flags mean "worth a look", never "confirmed abuse". Automated invocation can be legitimate — the automation policy is an open decision.
